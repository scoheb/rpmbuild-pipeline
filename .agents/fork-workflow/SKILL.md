# Fork Workflow Rules

This repository is a **managed fork** of
[konflux-ci/rpmbuild-pipeline](https://github.com/konflux-ci/rpmbuild-pipeline).
The following rules are critical.

## The Golden Rule

**Never edit root files directly.** The repo root is generated. All of these
paths are outputs of `make -C .hummingbird sync` and must not be hand-edited:

- `pipeline/` (Tekton Pipeline definition)
- `task/` (Tekton Task definitions)
- `docs/`
- `CONTRIBUTING.md`, `COPYING`, `README.md`
- `renovate.json`, `diff-flavor.sh`, `other-flavors.sh`, `test-konflux-build-locally`

These files are **safe to edit directly** (not generated):

- `.hummingbird/patches/*.patch` (fork-specific changes)
- `.hummingbird/Makefile`
- `.hummingbird/fork-workflow.md`
- `.agents/` and `.claude/` (agent skills)
- `.gemini/` (Gemini config)
- `.tekton/` (Tekton PipelineRun CI definitions)
- `.gitlab-ci.yml` is generated by patch `0001`, so edit that patch instead

## How changes work

1. Upstream source lives in `.hummingbird/src/` (a git submodule pointing to
   `github.com/konflux-ci/rpmbuild-pipeline`).
2. Fork-specific changes live in `.hummingbird/patches/` as ordered
   `git format-patch` files (`0001-*`, `0002-*`, etc.).
3. `make -C .hummingbird sync` copies upstream to root and applies patches.
4. `make -C .hummingbird check` verifies root matches upstream + patches (runs in CI).

## To make a fork-specific change

- Create or edit a patch in `.hummingbird/patches/`.
- Run `make -C .hummingbird sync && make -C .hummingbird check`.
- Commit the patch file changes **and** the regenerated root files together.

## Patch rules

- Patches must not revert upstream changes; they add fork functionality only.
- New fork-only files (e.g. `.gitlab-ci.yml`) must be created by a patch.
- Patches apply in filename order.

## YAML conventions

- 2-space indentation throughout, including dictionary values.
- The fork uses `__TASK_BUNDLE_TAG__` placeholders for task bundle refs
  (substituted at CI bundle-push time).
- Keep formatting compatible with the Renovate bot for OCI image reference updates.

## Key Make targets

```
make -C .hummingbird sync                # rebuild root from upstream + patches
make -C .hummingbird check               # verify root is in sync (CI runs this)
make -C .hummingbird regenerate-patches  # re-export patches with clean offsets
make -C .hummingbird update-upstream     # pull latest upstream into submodule
```
